## Findings

### F1 — Alert dialog has no accessible name or associated description

- **Severity**: ⚠️ WARNING
- **Impact**: 🏃 LOW — quick decision; fix is obvious and narrowly scoped
- **Dimension**: Safety & Quality
- **Location**: src/components/ui/alert-dialog/alert-dialog.tsx:41
- **Detail**: The React Aria `Dialog` renders a plain `<h2>` and plain description `<div>`, with neither an ARIA label nor `aria-labelledby`/`aria-describedby`. The installed React Aria implementation explicitly warns that a Dialog without `<Heading slot="title">` must provide a label. The destructive confirmation is therefore unnamed to assistive technology despite the plan's accessible-alert-dialog contract.
- **Fix**: Render the title through React Aria `<Heading slot="title">` and associate the description using React Aria's description slot or explicit ids.
- **Decision**: FIXED — rendered the title and description through React Aria's title and description slots.

### F2 — Destructive actions miss the planned hierarchy, safe focus, and target size

- **Severity**: ⚠️ WARNING
- **Impact**: 🏃 LOW — quick decision; fix is obvious and narrowly scoped
- **Dimension**: Plan Adherence
- **Location**: src/components/delete-plant-dialog/delete-plant-dialog.tsx:74
- **Detail**: The disabled and hydrated triggers use `variant="destructive"`, whose repository styling has a tinted destructive background instead of the required ghost treatment. The confirmation uses the same translucent variant instead of a solid destructive fill. Cancel is not marked as the default focus target, and both dialog actions inherit `h-8` (32px) rather than the required minimum 44px height.
- **Fix**: Use ghost + destructive text for both trigger renderings, give confirmation an explicit solid destructive treatment, add `autoFocus` to Cancel, and apply `min-h-11` to both dialog actions.
- **Decision**: FIXED — restored ghost destructive triggers, added Cancel autofocus and 44px actions, and made confirmation solid destructive.

### F3 — Reduced-motion and exit-animation contracts are not implemented

- **Severity**: ⚠️ WARNING
- **Impact**: 🔎 MEDIUM — real tradeoff; pause to reason through it
- **Dimension**: Safety & Quality
- **Location**: src/components/ui/alert-dialog/alert-dialog.tsx:35
- **Detail**: `prefers-reduced-motion:animate-none` is not a Tailwind variant used or generated by this project; the established variant is `motion-reduce:*`, and the production CSS contains no selector for the implementation's literal. The component also applies unconditional enter classes without React Aria's `data-entering`/`data-exiting` states, so there is no planned exit animation to suppress.
- **Fix**: Drive enter/exit classes from React Aria's `data-entering` and `data-exiting` states, and disable both with `motion-reduce:animate-none`.
  - Strength: Satisfies both the normal-motion and first-class reduced-motion contracts using states React Aria already exposes.
  - Tradeoff: Requires defining and visually checking the exit choreography, not only replacing one class prefix.
  - Confidence: HIGH — React Aria exposes both data states and the repository already uses Tailwind's `motion-reduce:` variant.
  - Blind spot: Browser-level animation timing was not exercised during this review.
- **Decision**: FIXED — added React Aria state-based enter/exit animations and disabled both under reduced motion.
